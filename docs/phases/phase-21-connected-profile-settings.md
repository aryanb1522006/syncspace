# Phase 21: connected profile settings cleanup

The completed account state is now a compact identity row with a Connected badge and a disconnect action. LinkedIn no longer repeats onboarding copy or offers name/photo fields that are already complete. First-time and partially complete accounts show only available, unapplied fields. Failed requests leave setup available for retry. The client filters its selected fields against the currently available fields before submitting, so stale hidden choices cannot be applied.

Completion is recognized from the last saved profile (not the unsaved editing form) and persisted in server-side LinkedIn account metadata. Migration 012 adds nullable per-field completion timestamps and recognizes already matching names/photos for existing users. Applying details records completion in the same transaction as the profile update. Editing a preferred name afterward does not reopen onboarding. Reconnecting the same account/details preserves completion; changed provider details reset only the corresponding field for review. Missing provider photos do not block completion. College authentication, provider scopes and private evidence rules remain unchanged.

The linked-account presentation follows the established account-management pattern of account identity, status and a relevant management action. See [GitHub's authorized app settings](https://docs.github.com/en/apps/using-github-apps/reviewing-and-revoking-authorization-of-github-apps) and [Google's linked-app management](https://support.google.com/accounts/answer/13533235). This is a design interpretation of those patterns, not a copy of their interfaces.

GitHub keeps its sync/reconnect actions and evidence-deletion choice. Its sync progress indicator runs only for an actual GitHub sync. Detailed LinkedIn export controls and instructions move to a separate, keyboard-accessible disclosure, collapsed by default. Imports still require preview/section confirmation and separate skill approval. Success notices clear after six seconds; errors remain actionable. Status labels, reduced button size, aligned account rows and non-stretched cards reduce visual noise on desktop and mobile. Demo notices use product language instead of environment-variable instructions.

Validation covers complete/partial/missing-photo states, existing profiles before flags are present, custom names after completion, reconnect with unchanged/changed provider details, failure/retry, stale field selections, existing-user migration and concurrent startup. Existing profile photo, session, import privacy and OAuth protections remain in the full regression suite.

Rollout: deploy `main` to the Render API so startup applies additive migration 012, and to Appwrite Sites for the frontend. No credentials or provider-console settings change. The frontend also recognizes matching saved details against older API responses, so existing users benefit while the API rollout completes. Refresh the profile after the frontend deployment. Do not seed production. Rollback retains the additive metadata columns; earlier code ignores them.
